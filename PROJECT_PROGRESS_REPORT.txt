11. MULTI-CLIP LIVESTREAM EXTRACTION & AUTONOMOUS AUTO-PUBLISHING RESOLUTION:
  * Problem Statement:
      1. Livestream clipping only produced 1 clip (or 2 clips) regardless of the number of clips requested (e.g. 3 or 4 clips).
      2. Autonomous auto-publishing was not uploading to YouTube Studio upon completion.
      3. User reported small-model canned refusals ("I'm sorry, but I can't assist with that.") when asking "clip a gta 6 video" in Chat.
  * Root Cause Analysis:
      1. Single-Clip Duration Bottleneck: Slice duration was hardcoded to 45 seconds in the frontend and backend. A 45s recording can mathematically contain only one 30–45s short. Subsequent candidate windows overlapped by >35%, triggering Non-Maximum Suppression (NMS) deduplication in clip_scorer.py to discard them.
      2. Auto-Publishing KeyError/NoneType: In livestream_clipper.py, the script called best_clip.get("video_path"). However, video_pipeline.process_video() stores the file path under the key "output_path". This caused Path(None) to throw a TypeError: "argument should be a str or an os.PathLike object where __fspath__ returns a str, not 'NoneType'", which skipped the upload with a warning.
      3. Playwright Browser Collision: When livestream clipping attempted to upload, the background SchedulerEngine was concurrently running an upload loop on the same browser profile directory (jarvis\browser_profile), resulting in SingletonLock / TargetClosedError.
      4. Chat Small-LLM Refusal: Local Qwen 1.5B occasionally defaulted to safety disclaimers before intent classification rules were applied.
  * Architectural Fixes Implemented:
      1. Dynamic Live Slice Duration Scaling:
         - Updated livestream_clipper.py: actual_duration = max(duration_seconds, int(num_clips * 45)).
         - Requesting 3 clips captures a 135-second slice; requesting 4 clips captures a 180-second slice.
         - Added partition guarantee in pipeline.py: if transcript candidate windows < num_clips, it automatically divides the recording into num_clips non-overlapping intervals, guaranteeing total_to_render == num_clips.
      2. Auto-Publishing Path Normalization:
         - Updated livestream_clipper.py to resolve best_clip.get("output_path") or best_clip.get("video_path").
         - Updated pipeline.py to populate both "output_path" and "video_path" in all returned clip dictionaries.
      3. Thread-Safe Browser Lock:
         - Added class-level _browser_lock = threading.Lock() in YouTubeBrowserUploader (youtube_browser.py) wrapping _run_in_proactor_loop().
         - Serializes all Playwright browser interactions across the background SchedulerEngine, livestream auto-uploader, and on-demand user uploads, eliminating SingletonLock crashes.
      4. Universal Siri-Style Tri-Mode Chat:
         - "clip a gta 6 video" routes via sub-50ms Controlled Mode directly to viral_autopilot.run_autopilot(topic="gta 6", privacy="public", upload_till_limit=True).
         - Refusal interceptors sanitize dialogue memory and suppress small-LLM refusals with instant loyalty confirmations.
